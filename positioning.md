# mdtask — принятые решения по месседжингу и сайту

Собрано из сессии 2026-06-10 (переделка лендинга). Это текущий источник правды для текстов
(сайт, README, доки). `messaging.md` — мёртвый документ, НЕ ориентироваться.

## Главный месседж

**«Один коммит: код, закрытие задачи и обновлённая спека».**
Это провабельный артефакт (`git show --stat`), не обещание. Hero делает заявление,
Living Specs сразу его доказывает.

Структура страницы: заявление → пруф → где живёт → инструменты → сравнение → setup.
Порядок секций: Hero → Living Specs → The tracker is your repo → CLI → It's just Markdown → Comparison → Setup → CTA.

## Жёсткие правила формулировок

1. **Никогда не писать, что ТУЛ закрывает петлю.** `mdtask done` только переключает чекбокс.
   `Implemented:` + правку прозы + коммит делает агент через скилл (`mdtask-next`).
   Правильно: «Your agent picks a task, builds it, and closes it in place».
   mdtask не содержит ни лупа, ни оркестратора (README: «ships no loop or orchestrator»).

2. **Единица = спека. Не «фича», не «домен».**
   Спека — один markdown-файл (auth.md = аутентификация целиком).
   Фичи (magic-link, password reset) — это задачи ВНУТРИ спеки.
   Слово «domain» в текстах запрещено — усложняет. Формулировка: «A spec is a single Markdown file».
   Убивать ошибку чтения «весь проект в одном файле»: файлов много, их набор = бэклог
   (на сайте это показывает `ls docs/specs/`).

3. **Слово «PRD» на сайте выпилено.** Везде `specs` / `docs/specs/…`.

4. **Проза спеки описывает только сделанное.** Если задача открыта — её поведения в прозе нет.
   (Из hero убрали строку про троттлинг, потому что AUTH-005 про рейт-лимит открыта.)

5. **`@blocked_by` — это custom field, поддержанный из коробки.** Парсится в свойства,
   подсвечивается в выводе. НЕ граф зависимостей: нет обхода, нет циклов. Не переклеймивать.

6. **Категория.** В лоб «task tracker» не вести (уводит к Jira), SDD-надзаголовок не лепить
   (наследие мёртвого messaging.md). Текущий H2 героя: «Spec-first task tracking in Markdown».

7. **Против OpenSpec / Spec Kit: заменяет, не дополняет — но заменяет их файловую церемонию**
   (папка сгенерённых spec/plan/tasks + слэш-команды), а не оркестрацию. Петля — забота агента.
   Блок #compare написан Максом руками («mdtask skips all of that») — не переписывать.

8. **Лицензия на сайте не упоминается.** Только «Open source · GitHub». Не писать «MIT».

## Факты о продукте (не перевирать в будущих текстах)

- `mdtask list` — по умолчанию только открытые; `--all` включает сделанные
- `mdtask done` — только `[ ]` → `[x]`, ничего больше
- `validate` — только целостность ID/метаданных (дубли, пустые теги, кривые @key)
- `archive` — задачи уезжают в `_archive.md`, поэтому «никогда не покидает файл» — неправда
- Скиллы: `sdd`, `mdtask-create`, `mdtask-next` (+ `mdtask`)
- На сайте `# Tasks` (H1) — это таргет незакрытой CLI-065; в реальных PRD сейчас `## Tasks`.
  Решено: для сайта похуй, не источник несоответствия

## Верстка (принятые константы)

- Отступ h2 → первый текст: `mt-4` везде; между абзацами `mt-3`; h3 в Comparison → `mt-2.5`
- В код-блоках между названием задачи и метаданными — два пробела (никаких выравниваний)
- ID задач в markdown-карточках приглушённые: подсвечивается только спец-форматирование
- Формат-карточка: на десктопе шрифт `text-base` НЕ трогать; ужатие только ≤860px (clamp), ≤560px как было
- Сноски под картинками: мелкие (`text-ui text-muted`), италик, по центру, разрыв строк осмысленный
- Чередование фонов секций сохранять (bg / panel / alt)
- Прод-URL: https://mdtask.dev (hash-URL воркера не светить)

## Открытое / не решено

- **Дог-фудинг** (PRD самого mdtask = его реальный бэклог) — идея валидная, блока на сайте нет
- `<title>` «Tasks and spec in one file» — читается как «весь проект в одном файле», не менялся
- Скептические вопросы без ответа на сайте: merge-конфликты на команде; не пухнет ли файл
  (ответ — archive); что мешает спеке протухнуть (ответ: `mdtask-next` не закрывает задачу
  без Implemented + правки прозы, а ревьюер ловит протухшую спеку в том же диффе)
